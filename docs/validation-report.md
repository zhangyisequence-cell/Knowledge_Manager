## 先复现再修补的问题

### Word 表格遗漏

原实现只遍历 `Document.paragraphs`。含“季度预算 / 12800”的表格上传成功，但生成笔记完全没有金额。新增验收先失败，再改为按文档顺序读取段落和表格；同一验收通过。

范围：普通段落和表格。页眉页脚、文本框、图表、复杂合并单元格、嵌套表格不在本次完整保真承诺内。

### 空白 PDF 假成功

原实现把“第 1 页”这样的系统页标题也计为正文，空白 PDF 仍生成笔记并标成功。新增验收先失败，再在解析后排除页标题并检查有效正文；无正文会报错。

审查后补充两个确定性回归：OCR 返回空文本、OCR 只返回页标题。暂时撤掉保护时两项均失败，恢复后通过，避免缺少 OCR 程序引发的错误掩盖真正的回归。

范围：拒绝完全没有正文的文档。文字页与扫描页混合 PDF 的逐页 OCR 覆盖，仍需进一步验证。

### 附件不能跨设备

原笔记使用 `file:///当前电脑路径`，原始附件在 Vault 外，单独同步 Vault 后附件失效。新增验收先失败，再将原始附件复制到 Vault 内 `_attachments/<content-id>/`，生成相对链接；验收通过。

验收还复制整个 Vault 到新路径，检查相对链接及附件字节一致性；长文件名先复现丢失扩展名，再修为只截断主文件名、保留扩展名。

范围：原始附件随 Vault 保存。网页正文中远程图片 URL 的离线替换仍未完成；这不等于所有网页图片都已离线化。保留上传原件及随库副本会多占用磁盘空间。

## 测试过程中的非产品问题

- 最初从主项目目录运行上游测试，3 个依赖工作目录的测试失败；改为上游目录执行后原有 35 项通过。`scripts/verify.py` 固化正确目录。
- 本地网页测试最初用带下划线标记，Markdown 转换正确转义下划线导致断言误报；换成无需转义的标记后通过，未修改网页解析逻辑。
- `uv` 安装媒体包时 Windows PE 资源更新遭拒绝访问；使用虚拟环境内 pip 安装成功，未改系统安全配置。
- 安装媒体依赖后，上游测试会触发默认语音模型下载。回归入口强制离线并隔离模型缓存；真实媒体验证由独立脚本显式触发。
- 测试输出包含 Starlette/httpx 及 AnyIO 的 2 条弃用提示，无测试失败；依赖兼容性仍需随版本维护。
- 锁定依赖中的 NumPy 要求 Python 3.12，因此本项目安装脚本与说明统一要求 3.12+；上游自身较低的版本声明不代表本项目锁定环境支持 3.11。
- 仓库初始不可读，用户调整后可以读取 main；公开读取不等于 Git 写入授权。已停止失败的登录尝试，没有获取、保存或输出任何 GitHub 访问令牌。

## 下一阶段的验收门槛

1. 用用户实际可打开的公众号文章验证标题、正文、图片、来源；遇到验证码或登录要求应报清楚原因。
2. 中文视频需模型可获取，并核对转写与原音频；不能用合成英语短片代替中文业务验收。
3. 真实 AI 应核对事实、金额、来源，不得把规则摘要或模拟响应记为 AI 通过。
4. 补齐去重、模型超时/失败重试、长文分段（当前 AI 输入直接截取前 80000 字符）、任务可观测性。
5. 分类当前是元数据字段，尚未验证固定分类词表与自动移动目录的管理流程。
6. 选择微信消息接入路径；本项目当前不包含微信聊天收件连接器。
7. 外网发布前补完整身份认证与访问限制；上游普通 API 不具备面向公网的隔离能力。
