# Ubuntu 知识服务器设计与验收边界

用户确认实际系统为 Hyper-V 中的 Ubuntu，允许在 Ubuntu 上部署（替代最初的 CentOS 说法）。此前 Windows 试点仅是验证环境，不代表 Ubuntu 已部署。

## 必须实现的结果

1. 微信仅承担资料提交与结果返回；解析、队列、归类、总结、提取在服务器执行。
2. 接收音频、视频、网页、文字、PDF、Word、Markdown、Excel 和手动输入。
3. 原件、提取正文、转写、笔记、任务状态保存在服务器；Obsidian Vault 是普通 Markdown 与附件文件夹。
4. 代码、部署配置、运维脚本及验收材料全部提交至用户的 Knowledge_Manager 仓库。私钥、密码、平台密钥、真实知识内容不进入 Git。

## 沿用和补齐

沿用已验证的 Knowledge Inbox 解析流水线和 Obsidian 写入。微信连接器只将消息转成统一收件任务，并返回受理、完成或失败状态。长任务由持久化队列执行，不能依赖微信回调长时间等待。微信入口类型需用户提供实际可配置的账号；未选择前不把某种平台的模拟接口当作微信已接通。

Excel 新增独立适配器：支持 XLSX/XLSM 与传统 XLS，保留工作表名、行列位置、日期、数值和文本；现代文件中同时记录公式与已有缓存结果，不执行宏或公式，不将缺失缓存当成计算结果。原文件照常随 Vault 保存。空文件、损坏文件和超出解析上限的表格明确报错，禁止默默截断后标记完整成功。

文档能力还须覆盖旧式 DOC；媒体必须用真实中文音视频核对转写；扫描 PDF 用中英文 OCR；网页须保存来源与提取快照，公众号文章遇到登录或验证码应返回清楚原因。AI 对长文分段处理并引用来源，不能把规则回退声称为智能归类总结。

## 部署与保存

Ubuntu 版本、地址、用户名、架构、磁盘和服务管理器必须在远端实查。100.64.186.105 为 Windows 宿主机，已能通过专用 SSH 密钥管理。目标虚拟机名为 Ubuntu，配置 4 GiB 内存、1 vCPU，挂载 Ubuntu 24.04.4 安装镜像。控制台实查停在 UEFI 启动错误；已切换 Linux 安全启动模板并卸载安装介质，保留虚拟硬盘，继续核实系统安装状态。

应用与数据分开，计划使用专用服务账户；程序目录 `/opt/knowledge-manager`，数据根 `/srv/knowledge-manager`（实际落盘前以目标磁盘容量、挂载点及现有资料为准）。Vault、原件、SQLite 数据库、模型缓存各自明确目录；升级替换程序时不覆盖数据。服务只经受控入口访问，微信回调需签名校验、发送者白名单和重复消息幂等处理。

每日一致性备份须同时覆盖 Vault、原件与 SQLite；备份结果校验散列、记录清单，保留多个历史版本。恢复演练在独立目录进行，核对数据库记录及原件字节。单盘多个副本不能证明磁盘损坏可恢复，外接盘或第二介质的实际位置需在部署时确定。
