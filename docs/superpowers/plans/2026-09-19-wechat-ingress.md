# 微信入口实现计划

沿用已确认的 Ubuntu 知识服务器设计。优先实现微信客服官方接口；没有账号配置时默认关闭，不暴露未认证接口，不宣称真实微信已接通。

1. 共用安全层：官方 AES-CBC 协议验签解密、接收方匹配、有界 XML；独立固定样本验证。
2. SQLite 保存回调通知、客服同步游标、原始消息、任务映射和待发送结果。同一页消息全部持久化后再推进游标；客服 ID + 消息 ID 去重；仅白名单用户消息可进入解析队列。
3. 通过现有持久化 jobs 表入库，确定性任务 ID 使中断后重试不会重置已完成任务。媒体先原子保存到服务器，再排队；错误保留明确原因。
4. 单个后台 worker 同步消息、接入解析、生成回复和发送。网络错误采用延时重试，遵守 48 小时/回复数限制；复用同一发送 msgid，区分 API 接受和真正送达。
5. 回调只接收官方已验证通知并快速应答；公开路由与管理 API 分开部署。代码测试使用固定或合成消息，不把模拟结果算作实际微信验收。
6. 实际账号、密钥、白名单和 HTTPS 回调地址由服务器本地配置。真实收件、文件、语音、视频、返回、重复回调和重启续处理通过后再完成验收。

本轮先实现安全层及持久化接入基础，并逐步联通 worker 和回调。所有代码、测试和说明提交用户仓库，知识和凭证排除在 Git 之外。
